# 粒子报告 3.1

Windows 后台采集、本地离线查看、局域网汇总、固定国内中心与签名更新。客户端界面和采集服务独立；没有 FRP 运行依赖，不通过公网穿透访问仪器电脑。本次不接短信、邮件等外部通知。

## 日常使用

1. 安装 `Lizi-Setup-3.1.10-x64.exe`，在本机桌面设置报告根目录，结构为 `根目录/YYYY-MM-DD/仪器子目录/*.txt`。
2. 在“中心接入”选择仪器类型、填写简短编号（例如 `A01`）并保存。编号自动转为大写，支持 1–24 位字母、数字、短横线和下划线；不再填写服务器地址、UUID、上传令牌或启用开关。
3. 中心地址固定为 **https://reports.abocidee.com**。管理员进入“仪器”批准接入，客户端自动上传。待批准、断网和停用期间仍保留本机报告与待传任务。
4. 客户端报告页只显示明细表，不提供记录表切换或“更多操作与信息”。日常操作保留日期、班次、当前班次、刷新、明细列开关和 Excel 导出；选中报告时可直接清除选择。中心网页仍保留记录表及扩展操作，后台采集与小程序不受影响。
5. “当前班次”按北京时间选择：07:00–19:00 白班；19:00 至次日 07:00 夜班；凌晨 7 点前选择前一天夜班。客户端首次打开默认当前班次；实际采集到新增或更新的仪器报告后自动返回当前班次，普通轮询、无变化扫描和就地更正不会打断历史查询。查看非当前班次时以醒目的黄色提示区分，并可一键返回；更正或导出进行中会在操作完成后返回。中心网页仍保持手动查询。Excel 导出保留一个入口，根据选择导出全部或选中报告；手机在表格内部横向滚动，数据列不裁剪。
6. 需要多年历史时，在中心接入的诊断展开项中安排历史日期补传，不会首次启动就解析整台电脑所有旧文件。

后台扫描、连接状态轮询和报告更新分开处理：已有表格不会因“数据准备中”提示反复上下移动，同一查询最多保留一个在途请求；报告内容未变时保留表格对象，真实数据变化仍实时更新。

本机不提供账号登录，目录、接入和局域网写操作仍需桌面持有的本机管理凭据。中心网页始终登录，普通查看用户不能管理仪器和版本。

### 数据更正（本机，界面不提示）

客户端明细表的数值支持就地更正，入口刻意不放在明面上：**双击**可改的单元格即进入编辑，回车或失焦保存，Esc 取消。页面没有按钮、图标或说明文字提示这个能力。

- 可改内容只有两项：**样品名称**（明细表“样品”列）与**单个测点强度**（开启“显示明细列”后的数值列）。
- 改样品名称时，**产线（炉号）与“总分析”标记按解析规则自动重推**（前导数字、名称含“总”或“z”）。
- 改单个测点时，**最大/平均/最小自动重算**（平均按整点取整，与解析结果口径一致）；仪器自己给出的指标（硬度偏差、粒径、前 25% 平均值/偏差等）保持仪器原值，不做推测性重算。
- **仪器原始 TXT 不被改写**：更正在索引里生效，原始文件仍是仪器输出。若该 TXT 之后被重新写入，重新索引会以文件内容为准覆盖更正。
- 更正以新版本上传中心（同一报告 ID，`sequence+1`），中心的当前值被替换，历史版本留在云端版本表；中心不提供修改入口，也不会改写设备上报的内容。
- 仅**数据所在设备的桌面**可直接改：接口要求回环地址加本机管理令牌，局域网对端与中心网页都无法修改。对端（其它设备）的报告只能查看，不能改。
- **小程序**是远程更正入口：“设置 → 管理员”输入服务端配置的管理密码，即可进入管理模式，单击报告样品名或测点修改，无需逐个开通成员白名单。原有 `users.can_edit` 白名单成员仍可在普通报告页长按编辑。两种入口共用中心队列（`cloud_edits`），设备下一次心跳（60 秒）取走后用上面完全相同的本地编辑路径生效，再以新版本回传中心；设备离线时排队保留，恢复后自动同步。管理页只在读到设备回传的新值后显示“已同步”。
- 远程更正不写中心镜像：中心只有在收到设备上报的新版本后才改变显示值，因此改动生效前看到的仍是旧值，这一点与仪器口径一致。
- 本机报告也会带设备 ID 用于显示来源，所以界面用单独的对端标记（`remote`）区分只读行；3.1.5 曾错误地以设备 ID 判断，导致客户端上所有报告都不可编辑，3.1.6 已修正。

## 中心管理与断连

管理页分为 **报告 / 仪器 / 版本 / 账户**，普通查看用户只有报告和账户。

- 仪器列表主要显示短编号、类型、名称/位置、连接状态、最后联系、待传数量和客户端版本；UUID、错误和诊断细节展开查看。
- 心跳每 60 秒发送；报告上传也更新最后联系时间。90 秒内为在线，90–180 秒为连接不稳，超过 180 秒为离线。状态每 30 秒检查并推送变化，浏览器也定期刷新，因此实际显示有最多一个检查周期的延迟。
- 没有新报告不等于离线。网络状态与采集错误分开：例如服务在线但未设置报告目录，会显示采集问题。
- 网络恢复自动上线和补传，无需“重连”按钮。离线不会自动停用、撤销授权或删除历史。
- “待批准”需要管理员批准；明显错误的待批准申请可以拒绝并释放编号。已有报告的仪器只能停用，历史保留。
- “已停用”是管理员主动撤销上传权限，不是网络故障；重新启用后原凭据继续有效，客户端自动恢复。
- 待传数未知、指标读取失败或管理页刷新失败会明确显示未知/过期，不能把失败当成待传为零。

公网设备申请采用本机自动生成并持久保存的随机秘密，中心只存哈希；未批准不能上传，错误秘密不能接管已有设备。申请正文、频率和待批准数量受限。提交第一条采集事件后锁定仪器身份，避免历史报告归属改变。

## 架构与仪器扩展

```text
仪器 TXT → Windows LiziService → 本机 SQLite + 持久待传队列
                       ├→ 本机桌面/浏览器查询、导出
                       ├→ 可选局域网配对汇总
                       └→ 固定 HTTPS 中心 → 中心 SQLite → 网页查询、管理
```

- `packages/core`：实际解析器、仪器目录、班次规则及发布验签契约。
- `packages/server`：本机采集、队列、局域网，以及按运行模式隔离的中心接收、仪器和版本管理。
- `apps/web`：共用 Vue 页面，客户端设置和中心管理按模式隔离。
- `apps/desktop`：Electron 窗口、本机管理授权及显式更新入口；不是采集核心。

采用 **统一客户端 + 独立仪器适配器**，不为每种仪器复制整套登录、安装、重试和管理程序。文件解析入口在 `core/src/instruments.js`，已支持类型目录在 `core/src/deployment.js`，中心按类型/模式版本验证报告。特殊串口、USB 或厂商 SDK 可以用独立采集进程接入同一协议。

当前仅 `strength` 强度仪 TXT 有真实适配，每个采集实例配置一个仪器身份和报告根目录。中心能管理多地点、多台已适配仪器；**未提供真实样本的其他类型不宣称已支持**。新增类型必须一起补齐解析、中心校验、显示和导出，不能只往下拉框添加名字。不同类型的特有字段不强行转换成强度值。

## 可靠性与数据边界

1. 文件稳定后读取；索引、指纹和不可变上报事件在同一 SQLite 事务提交。磁盘写失败不会把文件标记为已处理。
2. 中心完整验证批次，`synchronous=FULL` 提交后才返回确认；客户端精确匹配设备、事件、报告、版本及哈希，确认落盘后才删除队列条目。
3. 至少一次投递加持久去重：服务端保存成功但响应丢失时允许原事件重传，旧修订不能覆盖新修订。
4. 单批最多 32 个事件/2 MiB，单事件最多 1 MiB。数据和积压在磁盘，不整库读入内存。超限明确暂停，不截断报告。
5. 网络失败自动有界退避重试，不跟随重定向、不跳过 TLS 验证。待批准和停用定期检查中心状态；恢复批准自动补传。
6. 采集服务开机启动，退出桌面/托盘不停止后台。服务被停止、电脑休眠或关机期间不能采集；恢复后补扫磁盘上仍存在的文件并继续旧队列。首次读取前已删除的 TXT 无法恢复。
7. 今日/昨日优先；停机追赶和显式历史任务持久化、分批处理，历史范围单次最多 3660 天。非活跃旧日期后来修改需重新查询或安排补传。
8. 删除本机 TXT 不删除中心归档；成功上传不删除原文。仪器停用不删除报告，长期归档和积压需要足够磁盘。
9. 队列/凭据/权限错误保留任务并明确提示，不以重试按钮掩盖故障。完整数据目录及私有凭据应一并备份。
10. 从旧自定义服务器升级时，如还有未确认积压，拒绝自动切换固定中心，并跨重启保留阻塞；必须先处理旧目标积压。已排空才重建基线上报，版本号不回退。

## 局域网汇总

默认不开启 LAN、不改 IP/路由/DNS。按需配对，双方核对安全码批准；最多 8 个授权关系，TLS 指纹固定，每个来源独立断开/撤销/重连。

工作电脑仅查询各来源，不把汇总结果再次上传。一个来源离线保留最后缓存并标记不完整，阻止不完整汇总导出；公网断开不影响仍正常的局域网。LAN 报告只缓存于有界内存，不整库复制多年历史。已配对设备应协调升级，不把跨版本混跑当作已验收能力。

## 版本发布与客户端更新

管理员在中心“版本”上传 Windows 安装包和配套 `.release.json` 签名文件，再发布。安装包流式接收，单包最多 512 MiB，不进整块内存；整次上传最多 15 分钟，连续 30 秒无数据会中断。已发布版本不可覆盖或复用版本号。撤回停止提供该版本，最新版本回退到之前仍发布的版本，不会把已安装的新客户端强制降级。

客户端在“版本更新”手动检查、下载、确认安装。验证固定 Ed25519 公钥签名、版本、长度和 SHA-256，拒绝降级、错误来源和重定向。安装需要 Windows 管理员授权，用户取消则保留窗口；不会后台静默升级。Windows 服务只由正式安装程序按原升级流程替换，报告数据保留。

客户端的更新流量默认走对象存储。发布时安装包同时上传到腾讯云 COS 的发布桶（`lizi-release-1317280880`，北京），中心在 `/api/releases/latest` 返回 `url` 指向该对象；客户端下载该地址，失败或中断时回退中心 `/api/releases/:version/download`，已下载的字节用 HTTP Range 续传，最终仍按签名清单的 SHA-256 校验整包。中心不再把安装包重定向到对象存储：已部署的旧客户端以 `redirect:"error"` 取包，302 会让它们无法升级，因此该端点继续由中心直接流式提供。地址只允许 `packages/core/src/release-verification.js` 中 `RELEASE_MIRROR_HOSTS` 列出的主机，发布时中心同样校验。实测本机从 COS 下载约 13–17 MB/s，中心公网出口约 0.5–0.6 MB/s。

对象存储桶保持私有（禁止匿名列举），仅上传对象单独设 `public-read`。发布需要本机环境变量 `TENCENTCLOUD_SECRET_ID` / `TENCENTCLOUD_SECRET_KEY`（COS 上传）与 `LIZI_CENTER_USER` / `LIZI_CENTER_PASSWORD`（中心管理员登录）；任何凭据都不写入仓库和配置：

```sh
node scripts/publish-release.js --file release/Lizi-Setup-3.1.10-x64.exe --notes "本次更新说明"
```

脚本签名（与 `sign-release.js` 同一实现）→ 上传 COS 并匿名校验可下载 → 上传中心 → 发布并把 `url` 指向对象存储；重复执行同一版本不会覆盖已发布记录。

日常发版统一走以下入口；签名私钥路径通过 `LIZI_RELEASE_KEY` 提供，发布凭据使用上述环境变量：

```sh
npm run version:set -- 3.1.9
npm run release -- --notes "本次更新说明" --publish --deploy
```

该入口依次检查全部 workspace、锁文件和部署版本，运行回归测试，构建客户端与中心包，签名，备份并升级中心，再发布安装包。`--deploy` 使用 SSH 配置中的 `workspace-cn-new`，升级前停止本项目容器并备份完整数据卷；失败时尝试恢复旧容器。省略 `--publish --deploy` 可只构建并签名本地产物。已上传版本不可复用；发布后审查本次变更、中文提交并立即 `git push`，不自动提交工作区中其他文件。

3.0 及更早版本没有此更新入口，首次升级需运行 3.1 安装包；安装到原位置并保留原数据目录。3.1 之后再使用客户端内的检查、下载和安装流程。

桌面版本升级后，在本机后台健康时自动更新该站点的 Service Worker 和页面壳缓存，避免安装新版却仍显示旧设置表单。报告 IndexedDB 缓存、配置、凭据和后台数据库不清除；本机后台不可用时保留离线页面壳。

签名私钥仅在受保护的发布电脑保存，不进仓库、不上传中心。构建后签名：

```sh
node scripts/sign-release.js --key <受保护的私钥路径> --file release/Lizi-Setup-3.1.10-x64.exe --notes "本次更新说明"
```

脚本生成 `.exe.release.json`，只包含可公开的清单和签名。恢复发布环境必须保留私钥；换钥需要先安全更新客户端信任的公钥，不能只更换服务器上的文件。

## 开发与部署

Node.js >=22.13，发布后台固定 Node 22.22.2。

```sh
npm ci
npm run build
npm start                 # 客户端后台
npm run desktop           # 本机桌面
npm run start:server      # 独立中心
npm test
npm run dist
npm run dist:server
```

`LIZI_MODE=client|server`，两个模式必须使用不同的 `LIZI_HOME`；开发同时启动设置不同 `LIZI_PORT`，不要占用已安装服务的 3210。固定中心 URL 与发布版本在 `packages/core/src/deployment.js`，不提供客户端 HTTP 修改入口。

服务端分发包 `release/Lizi-Server-3.1.10.tar.gz` 包含预构建页面、源码、锁文件及 Docker 配置，不包含 Node 镜像、安装包、报告或凭据。Linux 解压后运行 `bash deploy/install-linux.sh`；默认容器只发布宿主回环 `127.0.0.1:13211`，非 root、只读根、命名卷 `lizi-server_reports` 持久保存 `/data`（数据库、仪器和 releases）。

国内中心部署于 `workspace-cn-new`，独立发行目录 `/opt/lizi-center/releases/Lizi-Server-3.1.10`，HTTPS 入口 **https://reports.abocidee.com**。反代模板为 `deploy/reports.abocidee.com.conf`，使用该主机现有泛域名证书续期链。Compose 信任紧邻一跳代理；后端端口保持宿主回环，代理覆盖转发头。安装包上传使用 512 MiB 请求体上限与流式反代。旧 `sq.abocidee.com`、`lizi.abocidee.com` 和旧 FRP 未因本项目部署而停止或切换。

首次管理员初始化需要中心数据目录中的 `setup-token.txt`，仅通过受保护渠道读取，不写入日志或公开文档。中心管理界面必须使用 HTTPS。升级/回退前停止本项目服务并备份完整数据卷及发布目录，不能运行中只复制单独的 SQLite 主文件。客户端同样备份完整 `C:\ProgramData\Lizi` 和原始 TXT；验证独立恢复后再清理旧备份。

验收记录保存在本机 `release/acceptance-3.1.10.json`。3.0 历史演练记录仍保留，不能用旧版本演练代替新版实际部署与更新验收。3.1.0 已撤回：实测发现 Windows 提权启动等待了整个安装进程树，导致向导已经启动却误报超时；3.1.1 改为只等待短暂的校验辅助进程，不覆盖旧版本文件。
