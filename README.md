# 粒子报告 3.0

本地采集与离线查看、局域网多设备汇总、HTTPS 可靠上报、中心服务器网页。3.0 不再内置 FRP，也不让公网网页穿透访问仪器电脑。本次不接外部通知渠道。

## 运行边界

- **客户端**读取自己配置的报告目录，解析并持久化结果和待上传事件。本地桌面查看、查询、导出不依赖公网；关闭桌面不停止 Windows `LiziService`。客户端不提供登录、账号管理或访问鉴权开关；旧配置中的鉴权开关不再生效，旧账号数据保留但不用于客户端访问。目录、LAN 和上传配置仍仅允许持有本机管理凭据的桌面修改，账号权限统一由中心服务器管理。
- **局域网汇总**由同一个客户端按需读取多个已配对设备。最多 8 个授权关系，可以分别添加来源和授权查看设备；只提供本机原始报告，不转发别人的汇总数据。历史数据不会整库复制到工作电脑，远端可见日期数据有租约和内存上限。
- **中心服务器**独立保存上报结果，提供网页查询、导出和设备管理。客户端离线时仍能查看已上传数据，但不能凭“在线”或“待传为零”认定报告齐全。
- 每台客户端只上传自己采集的报告，绝不上传局域网汇总结果。客户端与服务器必须使用不同数据目录，数据库不能混用。
- 当前真实解析器为 `strength`（既有强度仪 TXT），每个客户端配置一个稳定仪器标识和报告根目录。增加同类采集设备无需改代码。其他仪器类型须提供真实文件和字段含义后增加解析、校验、详情及导出适配；不会把未知格式当作强度数据接收。
- **报告页面**以完整测量表格为主体，桌面和手机均保留全部数据列；手机通过表格内部横向滚动查看，不自动切换为卡片。日期、班次、刷新与唯一 Excel 导出入口常驻；图片生成、整班次选择、历史快捷查询和诊断信息收进“更多操作与信息”。逐项/本页选择跨页保留，导出按钮随选择切换范围；数据不完整、读取失败和离线状态仍明确提示。

## 弱网和故障语义

1. TXT 在文件状态稳定后读取；索引、文件指纹、不可变上报事件在同一 SQLite 事务提交。队列写入失败不会把文件标记为已处理。
2. 服务端完整验证一批数据，SQLite `synchronous=FULL` 提交完成后才返回确认。客户端严格核对设备、事件 ID、报告 ID、版本与哈希，确认落盘后才删除对应队列项。
3. 传输为**至少一次**，服务端持久化回执去重。服务端已保存但响应丢失时，会用同一个事件重传；旧版本不会覆盖新版本。
4. 每批最多 32 个事件、2 MiB，一个事件最多 1 MiB；队列在磁盘，网络侧每次只读一批。单事件超限会保留并暂停，必须处理大小/协议问题，不自动删除或截断报告。
5. 网络错误、超时、HTTP 429/5xx 指数退避重试（含随机抖动，最长 5 分钟），遵守有界 `Retry-After`。单次请求 15 秒超时，不跟随重定向，不跳过 HTTPS 证书验证。
6. 令牌失效、协议拒绝、凭据缺失或存储异常会明确显示错误。更新令牌/修复存储后点击重试；不会因为心跳成功而删除任何报告。
7. 桌面关闭仍由后台采集上传。服务停止、关机期间无法采集；重启后继续队列和补扫。已入队的完整数据不依赖原 TXT 是否还存在；首次读取前已被删除的文件无法恢复。
8. 当天及昨天优先采集；持久化逐日检查点用于停机后追赶，新发现日期目录也会补扫。历史扫描每个有界批次让出执行权处理实时日期。
9. 首次选择目录**不自动解析多年旧目录**。需要服务器看到旧报告时，在客户端设置“补传历史报告”选择日期范围（首尾包含，最多 3660 天）。任务按根目录落盘，重启后继续；暂停上传时仍可采集、安排历史扫描。
10. 非活跃旧日期中的后来修改，需重新查询该日期或安排历史补传。切换目录不清空队列，也不删除原根目录的历史任务；切回对应根目录继续执行。
11. 首个事件生成后仪器标识锁定，设备 ID 不允许随意修改。有待传任务时禁止更换服务器，避免把旧队列误送给新服务器。排空后更换服务器会重建已索引报告的基线且不回退版本号；未索引历史需安排补传。
12. 删除本机 TXT 不会删除服务器归档。服务器保存报告修订和投递回执，需为长期积压及历史增长准备磁盘空间；不自动清理用户报告。

“断网可看局域网报告”指**公网断开、局域网仍正常**。某台来源连局域网也断开时，只能显示最后收到的缓存并标记不完整；缺失来源时阻止完整汇总导出。中心网页可以导出已收到的结果，会提示可能缺少尚未上传的数据。

## 本地开发

需要 Node.js >= 22.13（发布运行时固定 22.22.2）和 npm。

```sh
npm ci
npm run build
npm start
```

默认客户端监听 `127.0.0.1:3210`，数据目录 `.lizi`。开发网页可用 `npm run dev`；本机管理操作需通过桌面 `npm run desktop`。

客户端不提供登录、账户管理或访问鉴权开关，本地查看无需账号。升级时保留旧账号与鉴权设置数据，但不再用于客户端访问控制。报告目录、中心上传和局域网配置的写操作仍须通过本机桌面管理凭据；同源校验、上传设备令牌和局域网配对认证保持有效。

独立中心服务器：

```sh
npm run start:server
```

默认中心数据目录 `.lizi-server`，仍监听回环端口 3210。并行运行时分别设置 `LIZI_HOME`、`LIZI_PORT`，不要与已安装的后台服务争用端口。`LIZI_MODE=client|server` 可直接配置运行模式；对外部署必须使用 HTTPS 反向代理。

中心端始终要求登录。首次访问使用服务数据目录中的 `setup-token.txt` 初始化管理员；该令牌只能由服务管理员通过受保护渠道读取，不要发到聊天或提交仓库。中心端不能关闭鉴权，也没有本机目录、网卡、LAN 或 FRP 管理接口。

## 客户端安装与绑定

1. 安装 `Lizi-Setup-3.0.0-x64.exe`。默认仍是单机采集，上传和 LAN 不自动开启；不会自动改 IP、路由或 DNS。
2. 在本机桌面设置报告根目录，目录形如 `根目录/YYYY-MM-DD/仪器子目录/*.txt`；原 TXT 不修改、不删除。
3. 在“中心服务器上传”复制设备 ID。
4. 中心网页管理员在“设置 → 采集设备”登记该 ID、设备名称、稳定仪器标识；复制一次性显示的上传令牌到客户端。令牌关闭后无法再次读取。
5. 客户端填 HTTPS 地址、相同仪器标识和令牌，开启上传。检查待传数量、最早待传、最近确认时间和采集错误，不只看连接成功。
6. 需要旧报告时安排历史补传。无需为了上传开启局域网功能。
7. 令牌轮换会立即使旧令牌失效；对已撤销设备执行“重新授权并生成令牌”会恢复上传权限，客户端需更新令牌。撤销设备不删除其已上传报告。

服务器只保存令牌哈希，客户端私有凭据文件位于服务数据目录；浏览器不保存设备令牌。Windows 安装器限制本机管理凭据读取权限，HTTP 管理端口不对局域网开放。

## 局域网工作电脑

在各电脑开启局域网服务，工作电脑添加所需数据来源，双方人工核对安全码并批准。证书指纹固定校验，认证前即拒绝错误证书。每个来源独立断开、撤销、重连；一个来源故障不清空其他来源。

既有 2.2.x 单对端授权会迁移到多设备列表，保留设备 ID 和授权。已配对的各端应协调升级到 3.0，不把跨版本混跑当作已验收能力。需要反向查看时，应反向添加来源并批准；查看授权有方向，不自动互相开放。

安装防火墙规则仅放行同网段 TCP 3211 / UDP 3212。专用网卡向导仍需用户明确选择，不修改正常默认网关网卡；普通办公局域网无需使用向导。

## 中心端部署

打包：

```sh
npm run dist:server
```

生成 `release/Lizi-Server-3.0.0.tar.gz`，包含预构建网页、服务端源码、锁文件及 Docker 部署文件。归档不包含凭据或报告数据。

Linux 解压后：

```sh
bash deploy/install-linux.sh
```

需预装 Docker Engine 和 Compose。脚本只启动独立 `lizi-server`，默认发布 `127.0.0.1:13211`；不修改 DNS、现有 OpenResty/Nginx 配置，也不停止旧 FRP。可通过 `LIZI_HTTP_PORT` 选择其他回环端口。Compose 命名卷 `lizi-server_reports` 保存 `/data`，容器为非 root、只读根文件系统，日志按大小轮转。

现有 HTTPS 反向代理应指向该回环端口：

```nginx
location / {
    proxy_pass http://127.0.0.1:13211;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header Connection "";
    client_max_body_size 2m;
    proxy_buffering off;
    proxy_read_timeout 1h;
    proxy_send_timeout 30s;
}
```

TLS 证书继续由原反向代理管理；只有 HTTPS 443 需要公网访问。`LIZI_HOST=0.0.0.0` 仅用于容器内部，宿主映射仍是回环。普通启动默认只信任回环代理；Compose 显式设置 `LIZI_TRUST_PROXY=1`，信任紧邻的一跳 HTTPS 反向代理，以兼容 Docker 网桥转发。该配置要求后端端口始终只发布到宿主回环、代理重写转发头；不要把后端 HTTP 端口暴露公网。多跳代理应显式设置受信代理地址而非直接照搬单跳配置。

升级前停止该服务并备份完整数据卷（包含 SQLite/WAL、设置和初始化凭据），备份目录必须限制权限；验证备份能在独立实例恢复后再清理旧备份。不得只在运行中复制单独的 `lizi.sqlite`。客户端也需备份完整 `C:\ProgramData\Lizi` 及原始 TXT。

**发布代码和安装包不等于完成线上迁移。** `sq.abocidee.com` 是仍在使用的旧站；`deploy/legacy-installation.json` 只记录另一旧入口 `lizi.abocidee.com`，不是 3.0 的部署事实。先独立部署、注册设备、补传并核对报告，再授权切换实际域名；保留旧站回退，不先停旧隧道。

## 验证与发布

```sh
npm test
npm run dist
npm run dist:server
```

回归覆盖持久 ACK、重放去重、旧版本保护、批次原子性、鉴权撤销、磁盘写入失败、重启补扫、历史排程、局域网多来源及导出快照。真实弱网演练记录随本地交付物保存在 `release/acceptance-3.0.0.json`；它不代表两台物理电脑或实际公网部署已验收。
